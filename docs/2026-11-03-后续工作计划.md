# Neo 2 鸿蒙控制项目后续工作计划

日期：2026-11-03

本文汇总本次讨论的后续工作方向、建议顺序、第一版主动搜索范围及验收要求。本文是工作路线汇总，不代表各功能已经实现或完成真机验证；具体技术选型和实现细节在对应阶段确认。

## 一、总体目标

将现有无人机逆向工程稳定迁移到华为手机，逐步补齐视频、语音与原生任务能力，再通过统一控制接口接入 Agent，实现有反馈、可取消的任务执行。

主要工作包括：

1. 调试现有 Demo，定位视频冻结、状态转移异常、指令失效等问题。
2. 评测并选择适合无人机场景的 ASR，改善语音输入。
3. 继续逆向飞机原生主体检测与跟踪相关能力，摸清能力边界。
4. 实现简化版主动寻找：画面无人时，通过原地转向搜索，发现人物后停止搜索。
5. 接入 Agent，让 Agent 与按钮、文本、语音共用动作接口，并根据飞机反馈执行任务。

## 二、实施原则

- 先稳定基础通信、状态机和停止流程，再叠加自主行为。
- 不以“找出所有可能的 Bug”作为完成标准，改为维护可复现、可验证的故障清单。
- 区分请求发送、成功回复、实际执行及任务完成，不能只凭回复判断动作完成。
- 将抓包证据、离线测试、真机遥测和操作者观察分别记录。
- 对原 Python 工程尚未解决的问题，保留限制说明，不因迁移到 ArkTS 就认为问题消失。
- 每个阶段保留明确的验收条件，新增功能必须能停止、能取消，并允许人工接管。

## 三、阶段一：建立诊断能力并修复基础问题

### 3.1 分层定位故障

不能只将问题归为“逆向工程”或“ASR”，应按完整链路定位：

| 层级 | 主要排查内容 |
| --- | --- |
| 音频采集与 ASR | 是否采集到声音、是否误识别或漏识别、识别延迟 |
| 指令理解 | 文本是否正确转换为动作、方向、参数和时长 |
| 控制调度与状态机 | 状态锁、操作互斥、取消、停止抢占、旧任务残留 |
| 手机平台与网络 | Wi-Fi 选择、网络绑定、移动数据共存、切后台 |
| 协议与传输 | 实际发送、序号、匹配回复、重传、超时、注册与心跳 |
| 飞机执行 | 遥测是否显示执行、任务退出、下降或电机停止 |
| 视频处理 | 收包、组帧、解码、显示分别是否持续推进 |

先通过按钮或固定文本指令验证，再使用相同语义的语音测试。按钮也失败的问题不能直接归因于 ASR。

### 3.2 优先排查项

- 连接、初始化、断开、重连及路由序号衔接。
- 原 Python 版与 ArkTS 版的注册、心跳及连接时序差异。
- 视频持续收包但解码或显示冻结的问题。
- 准备、启动、停止、降落之间的状态转移。
- 停止或降落后，旧异步流程仍继续发送指令的问题。
- 原生任务停止后再降落，以及落地后开始新一轮操作的流程。
- 无回复或拒绝回复被界面显示为“完成”的问题。
- 录像请求与实际录像状态不一致、提前结束及退出清理。
- 应用切后台、链路中断、连续点击和并发操作。

### 3.3 日志与回放

- 为一次操作建立贯穿各层的操作标识和时间线。
- 记录输入、解析结果、状态变化、拒绝原因、发送报文、对应回复和执行证据。
- 视频分别记录最近收包、完整组帧、成功解码和实际显示的时间。
- 保存有容量限制的原始报文及视频诊断数据，避免只有最后几条文字日志。
- 支持使用同一份录音、报文和视频进行离线回放，复现问题并比较修复前后结果。
- 故障清单至少包含：复现步骤、证据、影响、所属层、修复状态、回归结果和真机验证状态。

### 3.4 验收要求

- 每个重点故障均有可复现步骤，或明确记录当前缺少的证据。
- 停止、降落和取消后，不再残留原任务的后续动作。
- 超时、拒绝、断联与实际完成有不同反馈。
- 视频冻结能够被识别，不将旧画面当作实时画面。
- 完成断网、延迟、乱序、超时和状态切换等故障场景的回归。

## 四、阶段二：统一动作接口并完成图传基础

### 4.1 统一控制入口

按钮、文本、语音和 Agent 应共用一套动作接口：

```text
语音 → ASR → 指令理解 ─┐
按钮／文本 ──────────┼→ 参数与状态校验 → 动作执行 → 飞机
Agent → 结构化动作 ───┘                         ↑
                                    遥测与执行结果反馈
```

- 统一动作参数、返回结果、超时、取消和重复请求处理。
- 明确哪些动作可以并发，哪些必须互斥。
- 支持读取当前能力、连接、任务、飞行和视频状态。
- 拒绝原因应可读、可记录，供界面和 Agent 使用。
- 保留现有飞控负责姿态稳定；应用侧仅执行经验证的有限动作。

### 4.2 图传基础

- 打通视频接收、组帧、必要的码流处理、HEVC 解码与手机显示。
- 对照原工程的参数过滤、有限帧序整理和损坏帧处理。
- 将耗时视频处理与控制通信隔离，使用有界队列并记录积压或丢弃。
- 明确区分收包停止、等待可解码画面、解码异常及显示冻结。
- 使用原抓包回放与持续真机运行共同验收；运行时长和阈值在测试方案中确定。

## 五、阶段三：ASR 评测与选型

目标：找到适合华为手机及无人机噪声环境的语音输入方案。

### 5.1 先确认运行条件

- 是否必须完全离线。
- 是否接受使用手机移动数据调用云端识别。
- 手机连接飞机 Wi-Fi 时，移动上网是否稳定可用。
- 对响应延迟、设备资源、费用和录音数据处理方式的要求。

### 5.2 建立真实场景测试集

- 安静环境与旋翼噪声环境。
- 不同说话距离、语速、口音及手机摆放方式。
- 方向、中文数字、时长、否定表达和相近命令。
- 重点覆盖“停止”“降落”的漏识别、误识别和延迟。
- 使用同一批录音比较端侧和云端候选方案。

### 5.3 评价与验收

- 不仅比较文字准确率，还要比较动作意图和参数准确率。
- 记录端到端延迟、误触发率、关键命令漏识别率和失败原因。
- 对识别结果的标点、数字、别名和过期结果进行确定性处理。
- 明确危险动作确认、确认过期和停止后清除待确认命令的规则。
- 距离和角度口令若仅通过时长估算，需要标定并明确其精度限制。
- 依据实际测试结果选型，本计划暂不指定具体 ASR 产品。

## 六、阶段四：逆向原生主体能力并摸清边界

### 6.1 分别验证四类能力

| 能力 | 需要回答的问题 |
| --- | --- |
| 检测 | 能发现什么目标，回传哪些类别、目标编号与框 |
| 选择／锁定 | 能否指定目标，还是只能由飞机自动选择 |
| 跟踪 | 目标移动、遮挡、多人交叉后，是否保持同一目标 |
| 重捕获 | 丢失后能否重新发现，是否可能切换目标 |

### 6.2 工作内容

- 从原工程已有的候选框、跟踪框和任务状态解析继续推进。
- 核验相关报文格式、字段含义、更新频率和不同模式下的可用性。
- 明确候选框、跟踪框、任务执行状态之间的关系。
- 测试人数、距离、光照、遮挡、目标运动及画面边缘等条件。
- 验证不同任务模式是否会启用或关闭检测消息。
- 未经验证的类别和状态枚举，不直接当作“检测到人”或“已锁定”的证据。

### 6.3 交付与验收

- 输出协议说明、证据索引、解析测试和能力边界表。
- 对已证实、推测和未验证字段进行区分。
- 主体数据过期后清除或标记失效，不能沿用旧框作为当前结果。
- 跟随、环绕和滑动变焦的能力验证与普通检测能力分别记录。

## 七、阶段五：简化版主动寻找人物

### 7.1 已确认的第一版范围

- 画面中没有人时，通过持续向左或向右原地转向来寻找人物。
- 先不做特定人物身份识别，不判断“这个人是谁”。
- 为判断搜索是否成功，仍需要基础的“画面是否有人”检测。
- 第一版不加入位移搜索。

### 7.2 建议的操作流程

1. 人工起飞并确认悬停，再手动开启搜索。
2. 画面持续一段时间无人，开始向选定方向缓慢转向。
3. 第一阶段采用“短时转向 → 摇杆回中 → 等待新画面 → 检测”的循环。
4. 连续多帧检测到人物后，停止搜索、摇杆回中并提示发现人物。
5. 达到搜索总时限仍未发现人物，则停止并报告未找到。

步骤 1、3、4 的具体实现形式属于建议；检测源、确认帧数、转向时长、等待时间和总时限待实施前确定。

### 7.3 状态与中止规则

- 至少区分：未启动、检查画面、转向、等待新画面、发现人物、搜索超时、已取消和故障。
- 视频冻结、画面过期或通信异常时停止搜索，不能当成画面无人。
- 检测应使用对应搜索阶段的新画面，避免旧结果影响当前决策。
- 人工停止或降落能取消整个搜索流程，旧流程不能继续发送转向指令。
- 当前转向若通过时长控制，应以累计时长限制搜索；未经航向测量验证，不能声称完成精确的一圈。
- 第一版暂不要求把人物转到画面中央，也不自动开始跟随。

### 7.4 验收要求

- 无人时能进入搜索。
- 出现人物时能结束转向并反馈。
- 视频或连接失效时能停止。
- 达到搜索时限时能停止。
- 人工随时可以取消，且没有后续残留动作。

### 7.5 待确认项

- 发现人物后，建议结束本次搜索、保持当前朝向并等待人工操作；该结束行为尚待用户确认。
- 建议人物离开后不自动重启搜索；是否需要自动重启，另行确认。
- 检测源选择：飞机原生检测、手机图传检测，或两者结合，依据前一阶段的能力摸底决定。

## 八、阶段六：接入 Agent

目标：让 Agent 通过结构化动作接口读取状态、执行有限动作并验证结果。ASR 仍可以作为语音入口，与 Agent 配合使用。

### 8.1 先做有明确终点的任务

- 查询当前连接、飞行、任务与相机状态。
- 请求拍照并检查后续结果。
- 在限定时长内执行动作并确认结束。
- 在主动搜索能力验收后，调用“开始搜索／取消搜索”接口。

### 8.2 控制边界

- Agent 不直接生成或发送原始协议包。
- 参数范围、状态限制、超时、取消和确认规则由确定性的控制层执行。
- 每个动作有可追踪标识，区分已接收、已发送、已回复、执行中、已完成和失败。
- 明确缺少执行证据时的结果，避免 Agent 将未知当作成功或自动重复飞行动作。
- Agent 失联、响应超时或退出时，按预先定义的策略结束本地任务。
- 人工停止、降落和接管始终能够中断 Agent 发起的任务。

### 8.3 验收要求

- 先使用模拟状态和离线回放验证工具调用与决策。
- 再用真机验证有限、可取消的任务。
- 无效参数、状态不满足和重复请求得到明确拒绝或去重结果。
- 完整保留 Agent 决策、动作调用和飞机反馈，以便归因。

## 九、建议推进顺序

| 顺序 | 主要工作 | 阶段产出 |
| --- | --- | --- |
| 1 | 日志、回放及基础故障排查 | 故障清单、复现证据、回归用例 |
| 2 | 统一动作接口、状态机及稳定图传 | 可供各输入入口共用的控制与反馈能力 |
| 3 | ASR 评测与原生主体能力摸底 | 语音选型报告、协议与能力边界表 |
| 4 | Agent 接入确定性任务 | 结构化工具接口及执行反馈验证 |
| 5 | 简化版原地转向找人 | 有限范围、可停止的搜索流程 |
| 6 | Agent 调用搜索及后续扩展 | 带观测反馈的组合任务 |

ASR 评测和主体能力摸底可以分别推进；主动搜索依赖稳定图传或经验证的原生检测源；Agent 调用搜索需要搜索功能先完成验收。

## 十、统一完成标准

每项功能交付时，应同时提供：

- 功能范围、使用前提和已知限制。
- 对应的协议证据或平台依据。
- 离线测试与回归结果。
- 真机测试记录及尚未验证的场景。
- 正常、超时、取消、断联和状态变化时的明确行为。
- 可供下一阶段复用的接口与日志。

最终以“行为有证据、故障能定位、任务能取消、人工能接管”作为跨阶段要求。

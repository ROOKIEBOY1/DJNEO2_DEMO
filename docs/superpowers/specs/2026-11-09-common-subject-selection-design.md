# 通用主体识别与确认

用户要求：主体识别和选择独立成通用能力。凡涉及主体的流程都应像组合运镜一样，显示模型选择的主体框，让用户确认，然后执行。

## 采用方案

抽出独立 SubjectSelectionWorkflow（扫描、选人、确认、有效期、取消），由 SubjectTaskWorkflow 编排起飞、通用选择、动作执行。滑动变焦、组合、独立跟随、主体环绕、指定主体拍照/录像和单独选人统一复用。原 GroundDollyWorkflow 仅保留兼容适配，不能复制一套选择实现，也不能用伪造 dolly 阶段来显示其他任务。

只放宽 UI 框的显示条件不能补上跟随的主体确认，因此不采用。为各动作分别复制流程会继续造成行为不一致，也不采用。

## 行为

- 独立跟随、环绕、滑动变焦在明确地面任务请求后可复用现有自动起飞，再扫描选人；悬停时直接扫描或复核。
- 指定主体拍照/录像、单独选人/切换复用主体确认；地面没有扫描条件时明确要求先起飞，不因拍照、录像或选人擅自增加起飞。
- 裸拍照、录像、起飞、降落、停止、下载和参数设置不进入选人。主体任务未确认时，停止/降落仍可即时打断。
- 默认隐藏扫描候选；仅展示模型选中的真实候选，用原五色渐变、粗线、安全内缩的框。即使只有一个候选或已锁定同一人，也须用户确认。
- 用户确认后立即隐藏框。滑动变焦/组合保留飞行方案与一键执行；跟随、环绕、指定主体拍照/录像、单独选人在确认后复核新鲜画面和同 ID 再执行，不增加第二个动作确认。
- 确认/方案阶段说“换个人”时，保留原动作与参数，重新选人并再次确认；不会把原拍摄意图悄悄改为单独选人，也不在任务正在执行时偷换目标。
- 模型识别意图与视觉选人分开。选人阶段只返回 select_subject/id 或 none；不允许在该阶段修改动作或参数。
- 多人且目标不明确时不默认第一个候选；相对切换排除当前主体。编号必须属于当前帧，沿用会话、轮次、取消、跟踪新鲜度和当前动作互斥检查。
- 确认30秒有效，过期/失联/降落/主体变化不得启动；异步旧回调不能覆盖新请求；双击不能重复执行。
- 本地素材、待回传票据、成片任务保留原语义。复用已验证的原生协议，不修改解码、起飞返回码或飞行结束判断。

## 接口与兼容

SubjectSelectionWorkflow 独立于 ArkUI、飞机协议和具体拍摄类型，依赖可替换 host，便于直接测试。SubjectTaskWorkflow 使用同一个选择组件。旧 groundDolly 快照和方法保留兼容，但真实实例改成通用编排器；新增 subjectTask 快照和通用确认入口供新 UI 使用。

AgentAction 对 photo/record_start/select_subject 增加 subjectRequired，用于无图意图阶段表达“需要选人”而不捏造编号；已执行动作仍必须持有本次候选编号。所有飞行任务类型进入通用入口，禁止地面无目标自动原生起飞绕过确认。

## 验证

覆盖地面/悬停、跟随/环绕/滑动变焦/组合/指定拍照/选人、同一目标复用/切换/多人歧义、确认前不执行、确认后隐藏与新帧复核、取消/过期/失联/重复点击、参数冻结、停止降落打断、素材与成片回归。离线验证和构建后生成安装包；真机任务效果须实际复测，不能以启动 ACK 或离线测试替代。

# 实时视频迁移设计

## 目标与现状

在现有 HarmonyOS 应用内直接显示飞机实时相机画面。现有 DroneSession 已接收 channel 2 报文，VideoAssembler 已迁移 Python 原版分片去重、冲突拒绝、超时及完整组帧；setVideoFrameListener 尚无消费者，Index 只有诊断占位。当前尚不具备实时预览。

原版参考：开发基地1/tools/video_stream.py，包括 _TimingParameterFilter、_LowDelayPictureOrder、HEVCDecoder、VideoReceiver；参考其回归测试与 captures 中实机数据。

## 方案

建议使用现有 ArkTS 通信层 + HarmonyOS Native AVCodec HEVC 解码 + XComponent Surface 显示。项目使用的 API 21 SDK 已提供原生解码接口。Native 工作线程处理码流和解码输入，ArkTS 只提交完整组帧、管理视图生命周期和读取统计。

其他方式：ArkTS AVPlayer 不能直接消费当前裸 HEVC 分片流，需要另行封装和流媒体服务；移植 FFmpeg 软件解码会增加依赖、包体和 CPU 消耗。采用系统原生解码较符合现有手机应用结构；若设备不支持，显示具体错误，不另行引入软件解码依赖。

## 数据链路

1. DroneSession 保持现有 UDP 接收、ACK 和组帧逻辑。完成帧交给预览服务，不等待解码。
2. 通过 N-API 将数据复制到有界队列；最多缓存 16 个完整帧且总容量不超过 8 MiB，单帧超过 2 MiB 拒绝。过载清理积压并重新等待参数与随机访问画面，避免无界延迟和损坏参考链。具体限制由实现者按实机样本验证后调整并记录。
3. 在视频线程迁移原版 Annex B NAL 处理、仅时序变化的 VPS/SPS 参数重复过滤，以及适用于已验证简单 I/P 流的有限帧序整理（3 帧、120 ms）。未知语法按原版保守透传，不把真实参数变化或损坏伪装成有效画面。
4. 解析有效 SPS 尺寸，收集 VPS/SPS/PPS，建立 HEVC 解码器并提交正确边界的 access unit。不能把原版可能拼接的多个画面作为单个解码输入；实现者需验证样本边界，按画面切分输入。时间戳使用单调时钟，不因短暂丢包无限缓存。
5. 解码输出渲染到 XComponent Surface，保持原始宽高比。动态尺寸变化、真实参数变化和解码错误通过串行生命周期处理；恢复需等待可解码随机访问画面。

## 页面与状态

替换“视频诊断”占位区为横向视频区域；连接且 Surface 就绪后自动预览，不增加飞机注册或相机模式切换步骤。显示等待码流、等待关键帧、实时画面、画面过期及明确错误。

分别记录最近完整组帧、解码输出、成功提交渲染的时间，以及收包年龄、队列积压、丢弃、参数过滤、帧序整理、解码错误。原生接口能证明的渲染提交不等同于屏幕实际呈现，状态与文档需准确区分。连续 2 秒没有新的渲染提交显示过期遮罩，避免旧画面被误认作实时；阈值可据测试调整。

## 生命周期与约束

Surface 销毁、断开、会话更换、页面退出和应用进入后台时停止并释放解码器与队列。回调带代次隔离，旧会话不得向新 Surface 渲染。Surface 恢复时仅在当前会话仍有效的前提下恢复等待新画面。当前 onBackground 已调用 foregroundOnlySafetyShutdown；保留该行为，返回前台不自动重连飞机，用户重新连接后再自动预览。重建和错误恢复有次数及时间边界，避免循环占用控制线程。

保留拍照录像、语音及飞控现有行为。视频链路不发飞行动作，也不因视频失败自动改飞机模式。暂不迁移 PC 的 HTTP/JPEG 浏览器预览、视频诊断落盘和主体框叠加；它们不是手机实时预览的必要路径。

## 验证

- 原有 45 项测试继续通过。
- 使用原版实机抓包和已知回归样本验证组帧、参数过滤、乱序修复、POC 回绕、真实参数变化、截断及未知语法。
- 验证有界积压、Surface 重建、断开重连及后台切换；统计不把收到报文当成已解码或已显示。
- 完成 API 21 arm64 构建。若手机连接可用，先检查设备与应用状态；覆盖安装可能中断控制，须确认当前飞机已落地停桨后进行。真机静止预览至少持续 5 分钟，包含后台恢复和重连，并记录是否持续渲染。
- 无法进行真机验证时明确报告构建与离线测试结果，以及尚未验证的显示、性能和硬件兼容性。

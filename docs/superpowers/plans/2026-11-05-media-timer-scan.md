# 下载误清理扫描轮询计时器

新的关键证据：18:20:21扫描成功、18:20:36进入原生运镜并完成两次录像；18:21:05.222首次HTTP下载启动后，扫描轮询的条件日志完全停止，之后起飞和降落仍执行，说明前轮扫描状态判断并不足以解释故障。

下载器 requestBound 把尚未创建的timer初始化为0，第一次armIdleTimeout直接clearTimeout(0)。0并非可靠的“无定时器”哨兵，共享计时器编号时会误清除其他组件（例如扫描轮询）。

实现：timer用undefined表示尚未创建，仅清理由下载器创建的句柄，清理后置undefined。新增共享计时器注册表回归测试，预置0号App轮询，完整经过HTTP消息与finally清理，验证App轮询存活、下载超时句柄全部释放。不改变飞行命令或扩大扫描状态限制。

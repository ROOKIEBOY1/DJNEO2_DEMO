# 手机实时视频

连接飞机后，向下滚动到“实时视频”。应用接收飞机现有 HEVC 码流并自动预览，无需单独打开图传或切换相机模式。

## 状态与诊断

- 等待视频码流：尚未收到完整视频组帧。
- 已收到视频，等待可解码画面：正在等齐参数和随机访问画面。
- 实时画面：最近有成功送显的解码帧。
- 画面已过期：超过 2 秒没有新的成功送显，旧画面上会覆盖提示。
- 错误文字：系统解码、显示绑定或恢复失败；连续失败达到恢复上限后，重新连接或重新进入页面再试。

诊断分别显示组帧、解码、送显数量和画面年龄。送显指系统接受渲染提交，并非对屏幕实际呈现时间的测量；收到报文不会被计为已显示画面。

## 迁移内容

- 保留 VideoAssembler 的完整组帧、去重、损坏拒绝及超时处理。
- 将 Python 原版的 HEVC timing-only 参数过滤和有限 I/P 帧序整理迁移到 C++。
- 按 Annex B 画面边界提交系统解码器，支持 SPS 尺寸提取和真实参数变化。
- Native 工作线程负责码流处理和系统硬件解码；ArkTS 接收线程只提交完整帧。
- 视频输入缓存上限为 16 帧、8 MiB，单帧最多 2 MiB。过载会清理积压并重新等待参数和随机访问画面。
- 连接更换、Surface 销毁、页面退出和进入后台时释放解码资源；保留原有后台安全断开规则，回到前台后仍需重新连接飞机。

没有迁移 PC 浏览器 HTTP/JPEG 服务或主体框叠加。手机采用系统 HEVC 解码器和 XComponent Surface，应用包不包含 FFmpeg。

## 开发验证

ArkTS 状态与生命周期回归：`node tools/test-core.cjs`（需要 DevEco Studio 随附的 Node 和 TypeScript，工具入口支持 NEO_TYPESCRIPT 覆盖）。

原生回归：`tests/native/hevc_test.cpp` 和 `queue_test.cpp`，样本来源及格式见 `tests/native/README.md`。手机系统可能拒绝执行通过调试工具上传的独立 ELF；此时应通过签名测试包运行测试，不修改设备安全策略。

构建需要 API 21 Native SDK，目标 arm64-v8a。`entry/oh-package.json5` 中的 libneovideo.so 依赖为本地类型声明；实现由 CMake 编译。
